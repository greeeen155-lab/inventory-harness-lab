# 04. 차별화·성취감 장치

> Phase 4 · 기준: [03-scenarios.md](./03-scenarios.md) 설계 원칙 P1~P12

## 전제

이 앱은 업무 도구다. 스트릭·배지·레벨 같은 게임화는 넣지 않는다.
막아야 할 이탈 경로는 단 하나다.

```
바빠서 안 찍음 → 숫자가 안 맞음 → 못 믿음 → 시트로 회귀
```

아래 세 장치는 이 사슬의 세 지점을 각각 끊는다.

| 장치 | 끊는 지점 |
|---|---|
| E1 유통기한 빠른 입력 | 안 찍게 되는 이유(느림)를 제거 |
| E2 오늘 할 일 카드 | 빠뜨려서 숫자가 틀어지는 것을 막음 |
| E3 팝업 정산 리포트 | 이 앱을 써서 얻은 것을 눈에 보이게 함 |

---

## E1. 유통기한 빠른 입력

### 왜
입고(S1)에서 가장 느린 동작은 상품 검색도 수량 입력도 아니라 **날짜 입력**이다.
캘린더 위젯은 연·월·일 3단계 탭이 필요하고, 창고에서 한 손으로 쓰기에 최악이다.
게다가 같은 상품에 유통기한이 여러 개 섞여 오므로(S1) 이 동작이 한 번에 여러 번 반복된다.

### 무엇
- **숫자 6자리 직접 입력**: `270331` → `2027-03-31`
- 숫자 키패드만 뜬다. 구분자·캘린더 없음
- **최근 사용한 유통기한 칩**을 위에 노출 → 같은 박스 로트를 이어 찍을 때 원탭
- 4자리(`2703`)만 치면 말일로 해석 (`2027-03-31`). 화장품·식품은 월 단위 표기가 흔하다
- 입력 즉시 아래에 사람이 읽는 형태로 확인: **`2027-03-31 (1년 7개월 남음)`**
- 과거 날짜·비상식적 날짜(10년 초과)는 저장 전에 경고

### 적용 화면
입고(S1) · 반품 재입고 · 팝업 정산의 로트별 잔여 입력(S9) · 실사 조정

## E2. 오늘 할 일 카드 — 홈 최상단

### 왜
이 앱에서 숫자가 틀어지는 원인은 입력 실수가 아니라 **빠뜨림**이다.
- 풀필먼트 3사 중 한 곳을 오늘 반영 안 함 → 그 거점 숫자가 실제보다 많음 (S5)
- 도착 문자를 받고 확인을 안 누름 → 재고가 `배송 중`에 갇힘 (S4)
- 만료된 재고를 방치 → 장부에만 남아 있음 (S12)

셋 다 **"하려면 할 수 있는데 잊는" 종류**다. 그래서 알림이 아니라 **체크리스트**여야 한다.

### 무엇

```text
┌─ 오늘 할 일 ─────────────────────┐
│                                  │
│ 풀필먼트 반영                    │
│   풀필먼트 A  ✅ 오늘             │
│   풀필먼트 B  ✅ 오늘             │
│   풀필먼트 C  ⬜ 3일 전     →    │
│                                  │
│ 미확인 배송        3건      →    │
│   풀필먼트 A · 4일 경과          │
│                                  │
│ 유통기한 만료      2건      →    │
│                                  │
└──────────────────────────────────┘
```

### 규칙
- **다 끝내면 카드가 사라진다.** 빈 카드가 남아 있으면 다음 날부터 안 보게 된다
- 각 줄은 탭하면 **바로 그 작업 화면으로** 간다 (읽고 끝나는 알림이 아니라 진입점)
- 표시 기준
  - 풀필먼트 반영: 마지막 반영이 **오늘이 아니면** 미완료
  - 미확인 배송: **7일 경과분만** 여기에 (3~5일은 정상, P9)
  - 유통기한: **이미 만료된 것만** 여기에. 임박분은 재고 목록에서 표시
- **위 세 가지 외에는 이 카드에 추가하지 않는다.** 항목이 늘어나면 체크리스트가 아니라 소음이 된다

## E3. 팝업 정산 리포트

### 왜
지금까지 팝업 판매량을 **아무도 정확히 몰랐다** (S9, 사고 다).
P2(영업)는 앱을 자주 쓰지 않으므로, 이 화면 하나가 P2가 이 앱을 쓸 이유가 된다.

### 무엇
정산 확정(S9) 직후 자동으로 뜨는 요약 화면.

```text
성수 팝업  2026.10.10 ~ 10.12

반출 160    판매 113    시식·증정 5    반입 42
소진율 74%

많이 나간 상품
  1. 샘플크림   45개   반출 50 · 90%
  2. 샘플세럼   32개   반출 40 · 80%
  3. 샘플토너   21개   반출 40 · 53%

거의 안 나간 상품
     샘플오일    3개   반출 30 · 10%
```

### 규칙
- **소진율 = (판매 + 시식·증정) ÷ 누적 반출.** 추가 반출(S8)이 있으면 누적 기준으로 계산한다 (P7)
- 판매와 시식·증정을 **나눠서** 보여준다 (F5-1)
- "거의 안 나간 상품"을 같이 보여준다 — 다음 팝업에 그만 가져가기 위한 정보다
- 종료된 팝업 목록에서 언제든 다시 열 수 있다

## 시나리오에 미치는 영향

| 시나리오 | 장치 | 효과 |
|---|---|---|
| S1 입고 | E1 | 유통기한 입력 3탭 → 1회 숫자 입력. 연속 입력 속도 확보 |
| S4 도착 확인 | E2 | 문자 받고 잊어도 홈에서 다시 눈에 띔 |
| S5 풀필먼트 일일 반영 | E2 | 3사 중 빠뜨린 곳이 즉시 보임 = 숫자 신뢰도 유지 |
| S9 팝업 정산 | E1, E3 | 로트별 잔여 입력이 빨라지고, 결과가 성과로 보임 |
| S12 폐기 | E2 | 만료분 방치를 막음 |

## 의도적으로 넣지 않는 것

| 뺀 것 | 이유 |
|---|---|
| **5초 실행취소 스낵바** | 사용자 판단으로 제외. 대신 **이력 화면에서 상쇄 기록으로 정정**한다 (F10). 저장 시 확인 단계는 여전히 두지 않되, 방금 입력한 건을 이력 최상단에서 바로 찾을 수 있게 한다 |
| 스트릭·배지·레벨·포인트 | 업무 도구에 부적합. 탭 수만 늘어난다 |
| 폐기 손실 월간 추이 | 데이터가 몇 달 쌓여야 의미가 생긴다 → v2 |
| 다음 팝업 반출 추천 | 팝업이 여러 번 쌓여야 근거가 생긴다 → v2 |
| FEFO 위반 기록 화면 | 위반이 드물어 별도 화면이 놀게 된다. 필요하면 이력 필터로 충분 |
| 총량 검산 줄 상시 노출 | 개발자에겐 유용하나 사용자에겐 의미 없는 숫자. 테스트로 보장한다 |
| 실사 유도 알림 | 풀필먼트는 매일 반영하고 자사창고는 직접 세므로, 별도 독촉이 없어도 된다 |
| 이메일·슬랙·푸시 알림 | 앱 내 표시만 (Phase 1 확정) |

> **알림은 늘어나는 순간 전부 무시된다.** 홈에 뜨는 것은 E2 카드 하나이고, 그 안의 항목은 세 종류로 고정한다.

## 참고 — FEFO는 장치가 아니라 기본 기능

"출고 시 유통기한 빠른 순"은 차별화 장치가 아니라 이 앱의 **핵심 요구사항**이다.
[01-requirements.md](./01-requirements.md) F5, 설계 원칙 P4에 이미 정의되어 있다.

- 출고·풀필먼트 반영·팝업 반출 **모든 감소 동작**에서 임박 로트부터 자동 배분
- 수량이 여러 로트에 걸치면 앱이 쪼개서 처리 (사용자는 계산하지 않는다)
- 다른 로트를 쓰려면 `변경` + 사유 입력
